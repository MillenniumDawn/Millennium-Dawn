# AI attribution prototype

This opt-in example reports explicit AI authorship labels in commit messages and
new repository text. It supports review of issue #4549. Findings are warnings;
they never change files, remove credit, rewrite history, or block a commit.
A failed or incomplete scan exits **2**, while a completed report exits **0**, even
when it contains findings. There is no enforcement flag or automatic hook/CI wiring.

Run from the repository root with Python 3.12+:

```bash
# A proposed commit message, including its body and trailers:
python tools/analysis/check_ai_attribution.py --commit-msg /tmp/message.txt

# Added lines in the index, including an initial commit and partial staging:
python tools/analysis/check_ai_attribution.py --staged

# New commit messages plus the net text added by a branch:
python tools/analysis/check_ai_attribution.py --base origin/main --head HEAD
```

`--repo /path/to/checkout` selects the repository for the last two modes. No GitHub
API is called. Issue bodies, issue comments and PR descriptions are not scanned.
Substantial AI-use disclosure in PR descriptions remains permitted by the Git
workflow guide. These reports do not establish whether code was written by AI.

## Review examples

Positive examples, each on its own line:

```text
# Author: Claude Code
// Author is OpenAI Codex
**Author:** Claude_Code
Co-authored-by: Claude Opus 5 (1M context) <noreply@anthropic.com>
Generated by Codex
🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

For a message containing `Generated by Codex` on line 1, the output is:

```text
WARNING "/tmp/message.txt":1: ai-footer: review explicit AI attribution
Report only: 1 finding(s); 0 skipped path(s). No files changed.
```

The diagnostic contains the source, line and rule, not the full message or email
addresses. Paths are JSON-escaped so filenames cannot inject extra output lines.
Commit sources use abbreviated hashes. A human decides whether a finding is an
unwanted footer, a quoted example, or required provenance; the tool never removes it.

These are not findings:

```text
Co-authored-by: Human Contributor <human@example.invalid>
Author: Claude Shannon
Author: CodexTools
Generated by tools/generate_validation_report.py
Reviewed with Codex.
AI assisted the draft; I reviewed and tested it.
# Copyright Claude Code Contributors; licensed under MIT
# Source: Claude Code documentation
is_ai = yes
```

Matching is case-insensitive and requires the complete attributed identity to be
a known alias: Claude Code, OpenAI Codex/Codex, ChatGPT, GitHub Copilot, or Claude
Opus/Sonnet/Haiku with optional version and context size. Spaces, hyphens and
underscores are accepted where shown in the matcher. Bare `Claude`, arbitrary
product names, prose/style signals and mixed human/tool identities are excluded.
This deliberately misses unknown aliases and more elaborate wording. It is not
an AI detector. Human names coinciding exactly with a tool alias still need review.

## Input boundaries and exceptions

- Staged mode reads Git blobs from the index, not the working files. Unstaged
  edits do not affect results. Unmerged index entries fail the scan.
- Branch mode resolves both refs to commits, scans messages in `base..head`, and
  checks the net additions from their merge base to the head. Base history is not
  scanned; pure renames and untouched legacy lines are not findings. Intermediate
  text added and removed within the branch is outside this prototype's scope.
- Missing refs, absent merge bases, shallow repositories, unreadable inputs,
  command failures/timeouts and invalid UTF-8 text fail visibly. No fallback to an
  empty successful result. Fetch complete history before using branch mode.
- UTF-8 BOM and CRLF are supported. Supported text suffixes are `.txt`, `.yml`,
  `.yaml`, `.md`, `.mdx`, `.py`, `.lua`, `.gui`, `.gfx`, `.asset`, `.mod`, `.json`,
  `.toml`, `.sh` and `.ps1`. Text blobs and message files are limited to 5 MiB;
  oversized text fails instead of silently skipping it.
- NUL-containing blobs, other suffixes, symlinks/submodules, `resources/`, and
  non-English localisation are explicitly listed as skipped with a reason.
  Symlinks are never followed and external diff/textconv helpers never execute.
- Exact-path exceptions with nonempty reasons live in
  `validation_config.json` under `check_ai_attribution.exempt_paths`. They cover
  selected policy/configuration documents, this example guide and its test file.
  There is no blanket Markdown, docs, `.claude/`, or test-directory exemption.
  Other intentional examples can be reviewed before adding one exact exception.
- Exception policy comes from the executing tool checkout's configuration, even
  when checking a different `--repo` or `--head`; it is not taken from the index.
  Commit-message checking has no path exemptions.

## Before any rollout

This draft intentionally leaves decisions open: supported aliases, exceptional
provenance/examples, whether PR bodies or squash messages need a separate check,
and whether only newly added lines or all text in touched files should be checked.
Human co-author credit, licenses and source provenance must remain intact. No
shared history should be rewritten. Existing attribution headers remain unchanged.

Review the warnings and triage a baseline before deciding on blocking severity.
A later integration would need a separately installed `commit-msg` hook, a staged
text hook, and an unprivileged PR job with complete history and coverage of
metadata-only changes. The content-validator artifact has no `.git`, so commit
checks cannot be added there unchanged. No integration is enabled by this draft.

Regression tests use temporary Git repositories and run with:

```bash
python -m pytest tools/tests/analysis/check_ai_attribution_test.py
```
