# Validation Pipeline — Pre-commit vs CI

Pre-commit and CI do not run the same hook set. Things that pass locally can still fail CI, and vice versa. Read this before wiring, judging, or debugging any validator.

## The validator test suite is a hard gate

CI runs `python -m pytest` on every PR touching `tools/` (`report-lib-tests` job in `tools-validation.yml`; testpaths in `pyproject.toml` cover all six test dirs). It must be green permanently — do not introduce regressions into the testing schema. A validator's behavior and its regression tests are one change: when a `*_test.py` in `tools/validation/tests/` (or the other test dirs) breaks because a validator changed, update the test to the new correct behavior in the same commit. If the test reflects the correct invariant and the validator regressed, fix the validator instead. Never delete or weaken a regression test to make it pass; the suite is the acceptance gate for validator wiring, and a red `pytest` blocks the PR regardless of how clean the validators themselves run. Run `python -m pytest` locally before merging any `tools/` change.

## When the coding pipeline runs

`coding-pipeline.yml` triggers on `pull_request` (`opened`, `synchronize`, `reopened`, `ready_for_review`, targeting `main`, content-path filtered). Two extra entry points cover open PRs that get no pushes:

- `workflow_dispatch` (inputs `pr_number`, `base_sha`) — manual re-run for an open PR, keyed on the PR's head branch as `ref`. The PR context is rebuilt from the inputs: `PR_NUMBER`/`HEAD_SHA`/`BASE_SHA` are `inputs.X || github.event.pull_request.X` everywhere they are used (workspace cache key, manifest, report). `detect-changes` skips `dorny/paths-filter` on dispatch (no checkout, no base ref) and treats every group as changed except `style` — the style job is diff-scoped, and a dispatch has no diff.
- `nightly-pr-validation.yml` — cron (06:00 UTC) + manual dispatch. Lists open PRs targeting `main` and dispatches `coding-pipeline.yml` per PR, so validation tracks the merge ref after main advances. `base_sha` is main's live head, resolved once per sweep: it is the only component of the workspace cache key that moves when main does, and cache keys are immutable, so a stale value would make `cache/save` a no-op and replay the previous run's tree. Fork PRs are skipped (dispatch refs must live in this repo); they still validate on every push. Two more classes are warned about and skipped rather than dispatched: a PR with no `refs/pull/N/merge` (it conflicts with main, and the pipeline checks that ref out) and a PR whose head branch predates the `workflow_dispatch` trigger (a dispatch runs the workflow file as it exists on `--ref`, so those branches need a rebase first).

A report comment is only created when a run has findings (#2702). A clean run never opens one, and what it does with an existing one depends on scope:

- **full** (dispatch only, every validator ran and passed): deletes the comment.
- **partial** (per-PR, only the changed groups' validators ran): rewrites the comment in place so it stops reporting an older commit, and leaves the PR uncommented if there was never a comment. It cannot delete, because a validator that did not run this time may still have live findings from an earlier push.

Partial reports label themselves in the verdict banner and metadata strip. Scope is computed in the `validation-report` job and passed as `--validation-scope`.

## The split

- Most content validators run **CI-only**: the `validate-core` / `validate-targeted` matrices in `.github/workflows/coding-pipeline.yml` are the gate. Their old `stages: [manual]` pre-commit hooks were removed (almost nobody ran them). On `git commit` only the fast subset runs — the `md-validate-content` dispatcher (`tools/precommit_validate.py`, which fans the commit-stage validators out in parallel), plus `check_common_mistakes.py` and `validate_defines.py`. To run a CI-only validator locally: `python3 tools/validation/validate_<topic>.py --staged --no-color` (drop `--staged` for a full-repo scan).
- `validate_ai_equipment.py` runs without `--strict` locally (coverage gaps would block all commits) but **with** `--strict` on CI. Equipment-coverage gaps that are tolerated locally will fail PR validation.
- `fix_loc_yaml.py`, `validate_localization_encoding.py`, `validate_mod_encoding.py` (all `tools/linting/`) are **pre-commit-only** — never run on CI. Web-UI edits or contributors with hooks disabled can land BOM or encoding regressions. (The old `check_braces.py` hook was absorbed into `tools/validation/validate_style.py`.)
- `validate_defines.py` runs on pre-commit against the live install and on CI against the committed `tools/validation/vanilla_defines.txt` manifest. Regenerate it (and every other vanilla-derived file) with `refresh_vanilla_data.py` after a HOI4 version bump (see [Refreshing vanilla-derived data](#refreshing-vanilla-derived-data)).
- `validate_ideas.py` is wired into both pre-commit (`--staged --strict`) and CI (`--strict`) — the undefined-idea backlog was cleared, so both sides gate identically.
- `validate_mios.py` runs in both pre-commit (`--staged --strict`) and CI (`--strict`): org-id format, `allowed = { original_tag = TAG }`, initial-trait naming, trait-grid x ≤ 9, non-empty `on_complete`. The org-id, `allowed`, and `on_complete` checks gate; trait naming and x-bounds are WARNING-severity — that backlog surfaces in reports without gating. `generic_`/`GENERIC_` shared orgs are exempt, as are `generic_`-named initial traits (they reference shared traits in `MD_generic_organization.txt`). Negative x is the mod's standard organic-layout first column, so only the upper bound is a finding.
- `validate_mios.py` also carries the **MIO localisation** checks (#2730). `header-text-not-tokenized` (ERROR) fires on a `tree_header_text` whose `text` is a literal quoted string — the engine prints it verbatim, so it never reaches the loc pipeline and cannot be translated. `header-text-loc-missing` (ERROR) fires on a header token with no English key, which renders the raw token as a column header. Both gate: the 118-literal + 4-orphan-key backlog was cleared in the same change, so they are clean on main. `trait-loc-missing` (ERROR) applies the same test to `trait` / `initial_trait` names and gates: its 31-item backlog (nameless FRA traits, dead key references, unlocalised generic keys) was cleared. A staged English-localisation change scans every MIO, so deleting a key cannot evade the check. Key resolution mirrors the engine: `TAG_<key>` wins if it exists, else the bare key; shared orgs have no owner tag, so only the bare key is tried.
- `validate_mios.py` also carries the **dead equipment_bonus** checks (#3044). An `equipment_bonus` value is a percentage of the equipment's declared base stat, so a bonus naming a stat the target equipment never declares — or declares as `0` — multiplies zero and does nothing. `mio-bonus-no-base-stat` fires when no equipment in scope declares a base (the issue's case: MANPADS carry no `max_organisation`, yet `GENERIC_krepost_state_defense_bureau_proximity_fuse` grants them +10% of it as its only bonus, so the whole trait is a no-op). `mio-bonus-partial-base-stat` fires when only some of the scope declares it, which is the half-wasted `limit_to_equipment_type = { AA_Equipment cnc_equipment_type }` shape. It is **not** raised inside an `initial_trait`: an org has exactly one, it cannot be split, and a `limit_to_equipment_type` narrowing it would restrict its `production_bonus` too, so partial coverage there is unfixable by design — a wholly dead stat in an `initial_trait` is still reported. `mio-equipment-type-unknown` fires on a token in `equipment_type` / `limit_to_equipment_type` / a nested bonus key that resolves to no equipment, and suppresses the bonus check for that block — a partial scope would report every stat the missing equipment supplies as dead. `mio-bonus-no-base-stat` and `mio-bonus-partial-base-stat` are **ERROR** and gate at commit stage as well as CI: both backlogs were cleared (782 and 293 respectively), so they are clean on main. `mio-equipment-type-unknown` stays **WARNING** with a 22-item backlog.
  - Scope for the flat `organizations/` form is the trait's own `limit_to_equipment_type`, else the org's `equipment_type`, else the `equipment_type` of the org named by `include` (one org, `HOL_gkn_aerospace_manufacturer`, needs that hop). The nested `equipment_bonus = { ARCHETYPE = { ... } }` form in `policies/` and `common/country_leader/defense_company_traits.txt` keys each block by its own archetype, so it needs no resolution.
  - `NON_STAT_BONUS_KEYS` excludes the per-archetype production keys (`production_cost_factor` and friends) that legitimately sit inside a nested `equipment_bonus` — they scale production, not a stat, so they have no base to be dead against. Without that exclusion `policies/` alone reports 71 false positives. `ZERO_BASE_EXEMPT_STATS` is the escape hatch for stats the engine gives a non-zero default; it is **empty** on purpose, since an entry silences a real finding. The open candidates are the naval `*_factor` keys (`naval_light_gun_hit_chance_factor`, `naval_heavy_gun_hit_chance_factor`, `naval_torpedo_damage_reduction_factor`, `naval_weather_penalty_factor`), which appear in `modifiers_documentation.md` as unit modifiers but in no MD equipment file — confirm in game before exempting.
  - The stat index is `tools/validation/equipment_stats.py`, which folds five sources: `equipments = { }` entries (a variant's stats union into its `archetype`), modules **scoped to the slots a hull actually accepts** (pooling every module hands tank chassis the ships' `max_organisation`), `duplicate_archetypes` clones plus their `for_each` stats and `substitute` twin, `type` categories (`equipment_type` accepts `submarine` as well as `attack_submarine`), and the `mio_cat_*` groups in `common/equipment_groups/`. It reuses the brace-walking helpers and hull/module resolver in `equipment_module_slots.py`. A stat counts only when something assigns it a **non-zero** value: `infantry_weapons_type` declares `ap_attack = 0`, which is no better than omitting it. `common/units/equipment` and `common/units/equipment/upgrades` are `replace_path`'d, so MD's files are the whole universe and no vanilla manifest is needed.
  - MIO validation therefore now reads `policies/`, `common/country_leader/`, `common/units/equipment/` and `common/equipment_groups/` on top of `organizations/` and English loc. All four are in the pre-commit registry and the CI `mios` path filter, because dropping a base stat in an equipment file kills bonuses in files it does not touch; staging one of them re-scans every org, the same way a staged English `.yml` already does.

- `validate_decisions.py` carries an ERROR-severity `missing-decision-log` check (complete_effect with effects but no `log =` line). It gates: the ~650-decision backlog was cleared, so it is clean on main.
- `validate_decisions.py`'s random-seed check (`validate_random_seed`, #2731) covers both `random_list = { ... }` and bare `random = { chance = N ... }`, and exempts `fire_only_once = yes` decisions (their roll resolves once, so a cached seed can never surface). It is ERROR-severity and gates: the 11-decision backlog was cleared in the same change, so it is clean on main. An explicit `fixed_random_seed = yes` counts as a deliberate choice; only an absent field is a finding.
- `validate_style.py` exempts `EH_` focus IDs via `_SHARED_FOCUS_PREFIXES` — the Event Horizon tree is generic (`event_horizon_generic_focus`) and `EH_` is its mod-wide domain prefix.
- `validate_unused_textures.py` is wired into pre-commit as `stages: [manual]` only. CI cannot run it, so invoke the manual hook when a texture audit is needed.
- `validate_gfx_references.py` runs **CI-only**, `--strict`. Its unused-sprite check is opt-in behind `--report-unused`: the ~6.7k WARNING backlog buried every real finding, and the script ref scan that feeds only that check is most of the runtime, so a default run does neither. Pass `--report-unused` for a sprite audit; staged runs skip the check either way. Set `MD_GFX_HIDE_UNUSED=1` alongside it to drop just the orphan list, leaving the case and duplicate findings readable.
  - Sprites the engine builds from mod data are **resolved into the reference set** by `_resolve_engine_refs`, not filtered out of the report. That distinction matters: a resolved reference still reports the sprite as unused once its backing declaration is deleted, and still reports it as miscased when the spellings diverge. Four sources, all membership-based (#2982):
    - `GFX_<FOCUS_FILTER_X>` for every `search_filters` token in `common/national_focus/`. Vanilla's `nationalfocusview.gui` carries `GFX_FOCUS_FILTER_POLITICAL` only as the template placeholder; the engine swaps in the real name.
    - `GFX_EMI_<module>` for every entry in an `equipment_modules = { }` block. The ~360 `GFX_EMI_afv_*` sprites that survive belong to an AFV module set that no longer exists.
    - `GFX_<TAG|graphical_culture|graphical_culture_2d>_ace_<m|f>_<n>`, plus the pool-less `GFX_ace_m_0` fallback, from `common/country_tags/` and `common/countries/`.
    - Anything a `[...]` template in a scripted-loc `localization_key` or scripted-GUI `image` can build, expanded to a regex over the defined set — this is what covers the 808 `GFX_missile_<TAG>_ID_<N>_icon` sprites built by `01_missiles_textures.txt`. A template with under four literal characters after `GFX_` is rejected: `GFX_[?topbar.GetTokenKey]` would otherwise mark the whole repo as used.
  - Two families stay true exemptions, since they are about ownership rather than resolution: equipment/tech/designer icons (`_is_engine_resolved_icon`) and any name vanilla also defines — a mod block under a vanilla name overrides vanilla's, so vanilla's own UI still resolves it (covers `GFX_MODIFIER_*`, `GFX_div_templ_*`, `GFX_EMSI_*`).
  - Case-sensitivity findings are split in two, because they are two different bugs. `sprite-ref-case` (ERROR) reports an English `£name` loc ref whose spelling matches a sprite only case-insensitively — the icon is simply gone on Linux. `unused-sprite-case` (WARNING) reports the mirror image: a sprite whose only reference is miscased, so the archive sweep leaves it alone. Non-English loc is out of scope (AGENTS.md), and a stray `£` before an accented word truncates at the accent (`£Réseau` → `£R`), which collides with short vanilla names.
  - `duplicate-sprite` (WARNING) reports a name defined more than once — engine load order decides which block wins — and `case-variant-sprite` (WARNING) reports names differing only in case. Both message whether the blocks share a texturefile: same art is a redundant split to collapse, different art is a silent override or two genuinely distinct sprites. WARNING, not ERROR: ~465 exact repeats exist on main and `--strict` gates on errors.
  - Sprite names in the generator-managed `.gfx` files come from the texture filename (`tools/gfx_entry_generator.py` builds `GFX_<stem>`), so a name fixed only in the `.gfx` is undone on the next generator run. Rename the `.dds`/`.png` and update `texturefile` instead.
- `validate_set_variables.py` runs **CI-only**, `--strict` (its unused-variable backlog was cleared). No pre-commit hook; run it directly (`python3 tools/validation/validate_set_variables.py`) for a local check.
- `validate_scripted_localisation.py` runs **CI-only**, `--strict` (its missing/unused scripted-loc backlog was cleared). No pre-commit hook; run it directly for a local check.
- `validate_file_paths.py` runs **CI-only**, `--strict`, in its own `validate-paths` job rather than either matrix. It reads path names from the git index (`git ls-files`), so it needs a checkout with `.git`; the workspace bundle the matrix jobs restore has neither `.git` nor `map/`. The job checks out with `filter: blob:none` and a sparse `tools` cone — the index already names every shipped path, so no content is fetched. `descriptor.mod` is read for `replace_path` directives, and a missing descriptor is a hard setup error: reading it as "nothing is replaced" would turn every inert case clash into a blocking one. Cross-references the committed `vanilla_paths.txt` manifest (CI has no HOI4 install); regenerate it after a game update via `refresh_vanilla_data.py`. Its within-mod case-collision check overlaps the pre-commit `check-case-conflict` hook on purpose — that hook only sees staged files on machines with hooks enabled, so web-UI edits and hook-less contributors bypass it exactly like the BOM fixers below.

- `validate_characters.py` runs in both pre-commit and CI (`--strict`, `characters` path filter). Its `trait-role-mismatch` check is ERROR and gates: a unit leader trait declares `type = land` / `navy` / `operative` (or `all`, or a `{ land navy }` list), and one from the wrong branch loads silently and never applies, so the leader ships with fewer traits than the script promises. Only the branch is compared — vanilla itself puts `type = corps_commander` traits on field marshals and `type = field_marshal` traits on corps commanders, so that split is not a finding (checking it produced 185 false positives). The `bold`-on-a-general backlog was cleared in the same change. `undefined-unit-leader-trait` is WARNING: 9 ALG/PHI references to traits nothing defines need content decisions, not a mechanical fix. `common/unit_leader` is `replace_path`'d, so the mod's files are the complete trait universe and no vanilla manifest is needed. Advisor and `country_leader` trait blocks draw from other pools and are not scanned.

- `validate_scientist_traits.py` runs **CI-only**, `--strict`, on a `scientist-traits` path filter (`common/scientist_traits/**` plus `interface/**`, since the sprite index is the other half of the check). No pre-commit hook; run it directly for a local check. All three findings are WARNING-severity, so nothing gates on the 19-item missing-medal backlog. The engine resolves a trait's medal to `icon = X` when declared and to `GFX_<token>` otherwise (`common/scientist_traits/_documentation.md`), and an unresolved name draws a missing-texture box on the character panel: the traits are live, assigned across 10+ `common/characters/*.txt` files. The sprite index is built **MD-only** (`include_vanilla=False`), which is the one non-obvious part: `interface/unitleaderwindow.gfx` is the only vanilla file defining `GFX_scientist_trait_*`, and MD replaces that path wholesale, so 13 vanilla names are dead in game and the default (vanilla-inclusive) index would pass them. That distinction is what splits `shadowed-scientist-trait-icon` (vanilla ships the `.dds`, MD's copy just needs the `spriteType` re-declared, a 4-line fix) from `missing-scientist-trait-icon` (no art anywhere). `stale-scientist-trait-icon-todo` catches the reverse drift: a `#TODO: ICON` marker left on a trait whose sprite now exists.

## Check notes

- `validate_file_paths.py` exists because Windows resolves paths case-insensitively and Linux does not. A mod file whose path differs from a vanilla one only in case replaces it on Windows but loads beside it on Linux, so the two platforms hash different file sets and cannot play multiplayer together — the Kaiserreich #28202 failure, whose culprits were `common/ai_focuses/usa.txt` against vanilla's `USA.txt` and friends. The checksummed set is not all of the mod: the game's own `checksum_manifest.txt` limits it to `common/**/{*.txt,*.lua}`, `events/**/*.txt`, `history/**/*.txt` and `map/**/{*.txt,*.map,*.bmp,*.csv}`, which is why `gfx/` and `interface/` case fixes never move a checksum. Collisions inside a `replace_path`'d directory are WARNINGs, not errors — the vanilla directory is not loaded at all there, so nothing diverges while that `replace_path` stands. `replace_path` is not recursive, so the check matches a parent directory exactly, never as a prefix.

- `validate_variables.py` carries a **clamp-range conflict** check (WARNING, `clamp-range-conflict`). It harvests every literal `clamp_variable = { var = X min = A max = B }` and flags any `check_variable` on `X` that compares against a value outside `A..B` (dead logic — always true or always false), plus the inverse scale slip: a sub-1 value compared against a variable clamped to a wide integer range. That second half is the `taliban_strength > 0.19` shape, the same failure class as the `threat > 40` trap in `general-rules.md`. It is deliberately anchored on the clamp rather than on observed value spread — a plain "this variable is compared on two scales" heuristic fires on `treasury`, `inflation_rate_var` and every percentage display variable, which legitimately use both. Variables only ever written by `set_temp_variable` are excluded: a clamp on a scratch parameter (`pp_gain`) constrains that one invocation, not the variable, so its range is no invariant for checks elsewhere.

- `validate_variables.py` also carries an **unlocalised available flag** check (WARNING, `unlocalised-available-flag`). HOI4 renders a `has_country_flag` line inside a player-facing `available` block from a localisation key named after the flag itself (vanilla does this for 672 of its 1680 country flags, e.g. `ARG_implemented_rural_reforms`), so an unlocalised flag shows the player the raw token as a requirement line. Findings are deduped per (flag, file). Checks wrapped in `custom_trigger_tooltip` / `custom_override_tooltip` / `hidden_trigger` are exempt because the wrapper supplies or suppresses the line, `visible` is excluded for the same reason as the untooltipped-`check_variable` check (a failing visible hides the object outright), and runtime-substituted flag names containing `@` are skipped as unresolvable statically.

- `validate_variables.py` also carries two **dynamic-modifier tooltip** checks, both WARNING. `variable-tooltip-missing-loc` flags a `tooltip = KEY` inside a variable effect whose key has no English loc entry — the engine renders the raw key, so the player reads `air_range_factor_tt` where the modifier line should be. It covers every non-temp variable effect (`set_`/`add_to_`/`subtract_from_`/`multiply_`/`divide_`/`clamp_variable`), is deduped per (key, file), and fires anywhere in `common/` or `events/`: a broken key is broken wherever it sits. `dynamic-modifier-tooltip-missing` is the other direction — an `add_to_variable` / `subtract_from_variable` moving a variable that backs a dynamic modifier with no `tooltip =` at all, so the modifier changes silently. The backing-variable map is built from `common/dynamic_modifiers/` at depth 1 only (depth 2 would drag `remove_trigger` / `enable` body keys in as variables), with `var:` / `global.` / `TAG.` prefixes and `^N` array indices normalised away; one variable can back several modifier keys, and the message lists every `<modifier_key>_tt` that resolves, or asks for the key to be added to `MD_dm_modifiers_l_english.yml` when none does. Unlike its sibling it is scoped to the block kinds the engine actually renders — `complete_effect`, `timeout_effect`, `remove_effect`, `completion_reward`, event `option`, MIO trait `on_complete` — which is what keeps `history/` bootstrap writes, `common/scripted_effects/` helpers (usually covered by one `custom_effect_tooltip` in the caller) and `on_actions/` out of the findings without a directory allowlist. `cancel_effect` is excluded deliberately: it fires on cancellation, not a player action. `hidden_effect` suppresses both checks at any depth, since it swallows every tooltip below it. Backlogs on main: 156 findings / 82 distinct keys, and 262 findings. Flip both to ERROR once cleared.

- `validate_events.py` carries a **date-gated scheduling** check (ERROR, `date-gated-not-scheduled`). MD fires its historical events from `common/scripted_effects/00_yearly_effects.txt` and uses the event's own `date >` check only as a guard, so an event carrying the guard with no scheduling entry is dead content: it is triggered-only, and nothing fires it. Only `date >` counts: a `date <` bound alone is an expiry guard on a chain event and says nothing about scheduling. Three exemptions: an event reachable from a scheduled ancestor in the event→event fire graph inherits that schedule; a fire from `common/national_focus/` or `common/decisions/` is a player-driven availability window with no scheduled moment to belong to; and if the scheduling file schedules nothing at all (a rename, or a scoping mistake) the check logs and skips rather than reporting all ~75 scheduled events. A fire from `common/on_actions/` is deliberately **not** exempt: a daily on_action waiting for a date is a poll, and the yearly effects are its intended home. Two on_action fire paths are modeled as schedules rather than dead content: a `random_events = { weight = ... }` pool weights its events by MTTH (the pool is the schedule), and a chance-rolled `random = { chance = N ... }` poll emulates MTTH and has no deterministic yearly slot. Both are exempt. The check ships as an **ERROR**.

- `validate_oob_units.py` slot-checks every `create_equipment_variant` through
  `tools/validation/equipment_module_slots.py` — ship, tank and plane designs alike,
  resolving module-driven slot unlocks and `duplicate_archetypes` clones first.
  All findings are ERROR. It also structurally checks `create_unit`
  effects: state scope, `owner`, block keys, a single-line division string
  naming a `division_template`, zero equipment/manpower factors, and the order
  of a template defined in the same file and effect path as the `create_unit`
  using it. It does not check that a referenced template is defined anywhere, so
  a template that only ever exists for the wrong country, or a `has_template`
  guard naming a template nothing defines, still passes. Its combined run gate
  covers `history/countries/`, `common/national_focus/`, `events/`,
  `common/decisions/`, `common/special_projects/`, `common/scripted_effects/`,
  `common/on_actions/`, `common/operations/`,
  `common/resistance_compliance_modifiers/`, and `common/scripted_guis/`, in
  both the pre-commit registry (`tools/precommit_validate.py`) and the CI
  `oob` path filter. `config_drift_test.py` derives both routes from
  `_CREATE_UNIT_SOURCE_PATTERNS`, so a new directory there fails the suite until
  both are updated. Findings are **errors**. Non-ship variants are skipped by
  design. Tank and plane slots are not validated anywhere yet. Their
  `allowed_module_categories` blocks are often empty, so the naval resolver
  cannot be pointed at them as-is.

- `validate_decisions.py` carries a **missing icon** check (WARNING, `missing-decision-icon`), opt-in behind `--missing-icons` and **not** wired into CI. Resolution follows the engine and differs per site: a decision `icon = X` is accepted if `X`, `GFX_decision_X` or `GFX_X` is defined (a bare name is the dominant MD convention and is **not** a bug — see `.claude/docs/decision-reference.md`); a category `icon = X` takes the `GFX_decision_category_` prefix instead, so a sprite that only exists as `GFX_decision_X` does not satisfy it; a category `picture` is always the full sprite name. Values already starting with `GFX_` are only tried verbatim, never double-prefixed. Dynamic `icon = { key = ... trigger = ... }` blocks contribute one check per `key`, and `[...]` values are skipped as runtime-resolved. Backlog on main: 355 decision + 79 category findings with vanilla sprites in view (596 without, see `sprite_index.py` below); flip to ERROR once cleared. The same `--missing-icons` flag drives the sibling checks in `validate_ideas.py` and `validate_focus_tree.py`. None of the three run in the workflow: sprite resolution is deliberately kept out of CI, so no matrix entry passes the flag and `run_all_validators.py`'s `_VALIDATOR_EXTRA_FLAGS` does not carry `decisions`. Run the validators by hand for an icon audit.

- `sprite_index.py` (shared by the event, idea, focus and decision icon checks) indexes the mod's `interface/*.gfx` plus a live HOI4 install when `include_vanilla=True`, and deliberately does **not** fold in the committed `tools/validation/vanilla_sprites.txt` manifest — the icon checks it fed are opt-in and not wired into CI, so the index stays install-based. A manual `--missing-icons` run without `HOI4_PATH` set therefore reports legitimate vanilla sprites (`GFX_decision_generic_*` and friends) as missing: set `HOI4_PATH` for a clean audit, or expect that noise. Re-wiring any icon check into CI means restoring the manifest fold-in first, since CI has no install. The event-picture check passes `include_vanilla=False` regardless: MD must not rely on vanilla event pictures.

- `validate_localisation.py` carries a **typo watchlist** check (WARNING, `loc-typo-watchlist`) against `.claude/docs/typo-watchlist.md`'s catalogued misspellings. It scans prose in loc values, excluding loc keys and runtime references (`[...]`, `$...$`, and `£...`). `it's` and `civilisation` are excluded as context-dependent. The backlog is clear; flip to ERROR when warning-only rollout is complete.

## Refreshing vanilla-derived data

CI has no HOI4 install, so five checked-in files stand in for the game. `tools/validation/refresh_vanilla_data.py` rebuilds all of them from a local install (auto-detected, or set `$HOI4_PATH`):

| Target    | File                                     | Read by                                                                        |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------ |
| `defines` | `tools/validation/vanilla_defines.txt`   | `validate_defines.py`                                                          |
| `docs`    | `resources/documentation/*.md`           | `validate_modifiers.py` (verbatim copies of the game's own `documentation/`)   |
| `gui`     | `tools/validation/vanilla_gui_files.txt` | `validate_gfx_references.py` (MD-authored vs vanilla override → ERROR/WARNING) |
| `paths`   | `tools/validation/vanilla_paths.txt`     | `validate_file_paths.py`                                                       |
| `sprites` | `tools/validation/vanilla_sprites.txt`   | `validate_gfx_references.py`                                                   |

```bash
python3 tools/validation/refresh_vanilla_data.py
python3 tools/validation/refresh_vanilla_data.py --only docs sprites
```

Run it after every HOI4 version bump and commit the diff. Stale data does not fail CI. It produces false positives instead, which is worse: a modifier Paradox added after the last refresh reads as a typo, and a sprite added in the same patch reads as an undefined reference.

The `docs` target is a straight file copy with no reformatting, so `diff -r resources/documentation "$HOI4_PATH/documentation"` is the staleness check.
